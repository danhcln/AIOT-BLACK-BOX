# Hardware & Schematic Review Standards

Adapted from ECC `rules/common/code-review.md` and `agents/code-reviewer.md` for KiCad hardware and schematic engineering.

## 1. When to Review

Review is mandatory:
- After any modification to `.kicad_sch` or python schematic builders
- During major revisions (e.g. REV8) as part of the full review cycle
- Before presenting final output or marking a task complete
- When resolving electrical ERC errors or routing issues
- Whenever a component pinout or net label is altered

## 2. Review Checklist

Before declaring any change complete, check:

- [ ] **Scope Containment**: Did the change stay strictly within the intended functional block?
- [ ] **Protected Power Architecture**:
  - `VBUS`: External USB-C charging/input source (NOT primary operating power)
  - `VBAT`: 18650 Li-ion battery rail (PRIMARY POWER SOURCE)
  - `5V_SYS`: Regulated 5V system rail (NOT renamed to `+5V`; NOT merged with `VBUS`)
  - `3V3_SYS`: Regulated 3.3V peripheral/logic rail (NOT generated by ESP32 DevKit for peripherals)
  - `GND`: Common return
  - `ADC_VBAT_SENSE`: Battery voltage monitoring divider connected to `GPIO1`
- [ ] **Peripheral Power Topology**:
  - ESP32 DevKit is NOT used as central power distributor for external peripherals
  - Both ESP32 and peripheral modules are LOADS of the system power architecture
  - Module breakout board input voltage requirements physically verified for `3V3_SYS` loads
  - ESP32 GPIO connections treated purely as signal paths, not power sources
  - No invented regulator part numbers or unverified DC-DC specifications
- [ ] **Protected Digital Interfaces**:
  - ESP32-S3 locked GPIO pin assignments untouched
  - I2C bus (`SDA`, `SCL`, pull-ups) intact
  - SPI bus (`MOSI`, `MISO`, `SCK`, `CS`) intact
  - UART lines (`TX`, `RX`) correctly routed
  - UI block (OLED, pushbuttons, LEDs, buzzer) unaffected
- [ ] **Drawing Rules Compliance**:
  - Power pin vertical hierarchy preserved: `VBUS`, `VBAT`, `5V_SYS`, `3V3_SYS` near top; `GND` at very bottom
  - Horizontal pin entries only
  - Net labels aligned and not overlapping symbols or wire junctions
  - Sheet boundary (A4) and title block preserved
- [ ] **No Silent Failures**:
  - No floating pins that should be terminated
  - No missing `no_connect` flags on unused real pins
  - No accidental short circuits or duplicate reference designators

## 3. Severity Levels & Evidence Requirements

| Level | Definition | Action Required |
|---|---|---|
| **CRITICAL** | Shorted power rail, inverted polarity, wrong pin voltage, invalid pinout, merging VBUS and 5V_SYS | **BLOCK**: Must fix immediately |
| **HIGH** | ERC electrical error, disconnected net, missing pull-up/down, overlapping graphics, ESP32 used as peripheral power source | **BLOCK**: Fix before reporting completion |
| **MEDIUM** | Rule violation (e.g. GND above VCC, vertical power pin), non-optimal routing | **WARN**: Fix or justify explicitly |
| **LOW** | Minor label spacing, non-functional text alignment | **NOTE**: Address if practical |

### Confidence-Based Filtering:
- Report only real issues you are >80% confident in.
- Cite the exact component reference, pin number, or line number.
- Name the concrete electrical failure mode or rule violation.
- **Zero Findings is Valid**: If the schematic passes ERC, matches drawing rules, and shows no regressions, return zero findings and verdict `APPROVE`.
